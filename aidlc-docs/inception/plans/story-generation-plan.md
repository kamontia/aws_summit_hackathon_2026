# User Stories 生成計画

## 目的

要件定義書をもとに、夫婦間API Gateway のユーザーストーリー、受け入れ基準、ペルソナを作成する。  
ストーリーはハッカソンMVP、デモ体験、AWSアーキテクチャ検討、後続のWorkflow Planningに使える粒度で整理する。

## ストーリー分解アプローチ候補

### A. ユーザージャーニーベース

ユーザーがアプリを開き、不満を入力し、プラン別に処理し、AI同士の家族会議を見る流れで整理する。  
デモ構成と最も相性が良い。

### B. 機能ベース

入力、リスク判定、言い換え、プラン差、疑似バイタル、家族会議、安全制御など、機能単位で整理する。  
実装計画とテスト観点を整理しやすい。

### C. ペルソナベース

不満を抱える配偶者、受け取る配偶者、審査員、運営・開発者など、利用者タイプごとに整理する。  
心理的価値やデモ訴求を整理しやすい。

### D. ハイブリッド

主要ストーリーはユーザージャーニーベースで整理し、受け入れ基準と補助ストーリーは機能ベースで補完する。  
本プロジェクトではこの方式を推奨する。
