# ペルソナ定義: 夫婦間API Gateway

## 1. ペルソナ設計方針

User Stories Planning の回答に基づき、主役は **不満を入力する配偶者** とする。  
相手側の配偶者は補助ペルソナとして扱い、家庭全体の体験も補助的に表現する。

価値表現は、以下の流れで設計する。

- 序盤: 家庭内あるあるとして笑えること
- 中盤: Standard中心の事業性・プラン差分
- ラスト: AI同士の家族会議によるブラックユーモア
- 安全性: User Storiesでは標準粒度で扱い、詳細な同意・監査・承認設計は後続設計へ送る

## 2. 主要ペルソナ

### P-01: 不満を入力する配偶者

| 項目 | 内容 |
|---|---|
| 名前 | 佐藤 美咲 |
| 年齢 | 34歳 |
| 家族構成 | 夫と子ども1人 |
| 状況 | 共働き。朝の家事、保育園準備、仕事の準備が重なりやすい |
| 主な悩み | 家事分担への不満を伝えたいが、言い方を間違えると喧嘩になる |
| 期待 | 自分の不満を、責め言葉にならない形で相手に伝えたい |
| 恐れ | 我慢しすぎて爆発すること、または伝え方で関係が悪化すること |
| サービスに求める価値 | 言いにくいことを入力するだけで、相手に合わせた表現に変換してほしい |
| 関連ストーリー | US-01, US-02, US-03, US-04, US-05, US-06, US-07 |

### 利用動機

美咲は、洗い物や保育園準備などの負担そのものよりも、「それを夫にどう言うか」に疲れている。  
夫を責めたいわけではないが、自分だけが気づいて動いている感覚があり、朝から揉めるのも避けたい。

### 成功状態

- 不満をそのまま入力できる
- 地雷ワードや炎上リスクに気づける
- Standardプランでは細かい指示なしで自然な文面が得られる
- 最終的に、AI同士の家族会議が成立する様子を見て、便利さと怖さの両方が伝わる

## 3. 補助ペルソナ

### P-02: メッセージを受け取る配偶者

| 項目 | 内容 |
|---|---|
| 名前 | 佐藤 健太 |
| 年齢 | 36歳 |
| 家族構成 | 妻と子ども1人 |
| 状況 | 共働き。仕事の繁忙期で家庭内タスクの優先度が下がりがち |
| 主な悩み | 急に責められたように感じると防御的になる |
| 期待 | 依頼の意図を落ち着いて理解したい |
| 恐れ | 自分が責められていると感じ、会話が喧嘩になること |
| サービスに求める価値 | 相手の不満を攻撃としてではなく、具体的な依頼として受け取りたい |
| 関連ストーリー | US-03, US-04, US-06, US-07 |

### 利用動機

健太は悪意があるわけではないが、家庭内タスクの見落としが多い。  
「今やろうと思ってた」と返してしまい、結果的に火に油を注ぐことがある。

### 成功状態

- メッセージが責め言葉ではなく依頼として届く
- 何をいつまでにすればよいか理解できる
- AI同士の家族会議で合意されたタスクを確認できる

## 4. 家庭単位ペルソナ

### P-03: 共働き家庭

| 項目 | 内容 |
|---|---|
| 名前 | 佐藤家 |
| 構成 | 夫婦、子ども1人 |
| 状況 | 朝と夜に家事・育児・仕事のタスクが集中する |
| 主な悩み | 小さな不満が積み重なり、突然喧嘩になる |
| 期待 | 家庭内摩擦を減らし、タスク合意を簡単にしたい |
| 恐れ | 便利になりすぎて、夫婦が直接話さなくなること |
| 関連ストーリー | US-01, US-05, US-07, US-08 |

### 成功状態

- 家庭内の議題が整理される
- 家事・育児の合意が見える化される
- ラスト画面で「家庭内摩擦: 低下」「直接会話: 0件」という風刺が伝わる

## 5. デモ視聴者ペルソナ

### P-04: ハッカソン審査員

| 項目 | 内容 |
|---|---|
| 名前 | AWS Summit ハッカソン審査員 |
| 状況 | 短時間で多数の応募・発表を評価する |
| 主な関心 | テーマ適合、AWS活用、実現可能性、事業性 |
| 期待 | 一目で笑えて、後から怖くなる企画を見たい |
| 懸念 | ブラックユーモアが安全性や倫理面の懸念として見えること |
| サービスに求める価値 | 風刺でありつつ、Guardrailsや安全制御への配慮があること |
| 関連ストーリー | US-08, US-09, FS-01 |

### 成功状態

- 「夫婦間API Gateway」という名前とテーマが記憶に残る
- 家庭内あるあるとして笑える
- 最後にAI依存の怖さが伝わる
- AWSマネージドサービスの使いどころが説明できる
- 事業性があるサービスとしても見える

## 6. ペルソナ間の関係

| 関係 | 説明 |
|---|---|
| P-01 -> P-02 | P-01が不満や依頼を入力し、P-02が変換後のメッセージを受け取る |
| P-01 + P-02 -> P-03 | 個別のやり取りが家庭全体の合意形成につながる |
| P-03 -> P-04 | 家庭内摩擦が下がる一方で直接会話が減る、という風刺が審査員に伝わる |
| P-04 -> 全体 | テーマ適合、AWS活用、事業性、安全性の観点で企画を評価する |

## 7. ペルソナ設計メモ

- 主役は P-01 とする
- P-02 は補助ペルソナだが、受け取り側の体験を無視しない
- P-03 はAI同士の家族会議を説明するための家庭単位ペルソナとして扱う
- P-04 はハッカソン特有の成功条件を整理するために含める
- Proプランは将来拡張として扱うため、MVPの主要ペルソナ体験には含めすぎない
