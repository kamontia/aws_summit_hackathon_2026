# AWS Summit Hackathon Proposal: 夫婦間API Gateway

## サービス名候補

### 本命

1. **夫婦間API Gateway**
   - AWSサービス名との掛け合わせがあり、AWS Summitのハッカソン文脈で覚えてもらいやすい。
   - 「夫婦間の会話を直接通さず、AIがルーティング・変換・制御する」という風刺が一瞬で伝わる。

2. **言っといてAI**
   - 最も直感的で、サービス内容が一瞬で伝わる。
   - 一般ユーザー向けのアプリ名、または機能名として使いやすい。

3. **家族会議Proxy**
   - 技術者・AWS文脈に寄せやすい。
   - 「家庭内の会話をプロキシする」という風刺が効く。

4. **家庭内交渉代行AI**
   - 何をするサービスかは明確。
   - 少し硬いが、企画書や審査資料では説明しやすい。

### コメディ寄り

5. **それ言うといて**
   - 関西弁風で軽く、家庭内あるあるに寄せやすい。

6. **角が立たない君**
   - 依頼・不満・謝罪を丸くする機能が伝わる。

7. **家庭内SLA**
   - 家事や育児を業務システムのように扱うブラックユーモアに向く。

### ブラックユーモア寄り

8. **会話レス家族**
   - 最終的に直接会話がなくなる風刺を強く出せる。

9. **DirectTalk 0**
   - ラスト画面の「直接会話: 0件」と相性が良い。

10. **Proxy Family**
    - 少し海外SaaS風。
    - 事業性を強く見せる場合に使いやすい。

## 推奨サービス名

応募時のメイン名称は **「夫婦間API Gateway」** を推奨する。  
アプリ内のボタンや機能名として **「言っといてAI」** を併用する。

理由は、AWSサービス名を想起させる名前で審査員に残りやすく、「家庭内の会話を直接通さずにAIが中継する」というサービスの構造と風刺が同時に伝わるため。

> 夫婦間API Gateway  
> 家庭内の言いにくいことを、AIがいい感じにルーティングする交渉代行サービス

## 企画概要

**夫婦間API Gateway** は、共働き家庭や同居生活で発生する「言いにくいこと」を、AIが角の立たない表現に変換し、必要に応じて相手への伝達まで代行する家庭内コミュニケーション支援サービスである。

洗い物、ゴミ出し、保育園準備、週末の買い出し、義実家対応、家計相談など、家庭内の衝突は大きな事件ではなく、小さなすれ違いから始まる。  
しかし本当に疲れるのは、家事そのものだけではない。「それを相手にどう言うか」という精神的な負荷である。

夫婦間API Gatewayは、この負荷をAIで肩代わりする。  
一見すると家庭を平和にする便利なサービスだが、便利すぎるあまり、家族は自分の言葉で向き合う力を失っていく。

## 一言ピッチ

> 家庭内の喧嘩をAIでなくす。ただし最後に、会話もなくなる。

## 背景

日本では共働き世帯が増え、家事・育児・仕事を並行する家庭が一般的になっている。  
その中で、家庭内の小さな依頼や不満は、内容以上に「伝え方」が問題になりやすい。

例えば、洗い物が残っていること自体は数分で解決できる。  
しかし、「また私がやるの？」「今やろうと思ってた」「その今っていつ？」という会話は、1日の空気を悪くする。

夫婦間API Gatewayは、この小さくて重い摩擦に着目する。  
社会課題としては家庭内コミュニケーション支援だが、ハッカソンではそこにブラックユーモアを加え、「AIに頼りすぎると、人は関係性を引き受ける力まで失う」という風刺として表現する。

## 解決する課題

- 家庭内で言いにくいことを伝える心理的負荷が高い
- 家事・育児・生活タスクの依頼が、責め言葉として受け取られやすい
- 小さな不満が蓄積し、突発的な喧嘩につながる
- 謝罪やフォローの言葉が下手で、さらに関係が悪化する
- 忙しい家庭ほど、冷静に話し合う時間と余裕がない

## 提供価値

### 表向きの価値

- 言いにくいことを、相手に合わせて柔らかく伝えられる
- 感情的な表現や地雷ワードを送信前に検出できる
- 家庭内のタスクや不満を、会話しやすい議題に変換できる
- 謝罪やフォローアップまで支援できる

### 裏の価値

- AIが家庭内の面倒な対話を肩代わりする
- ユーザーは自分の言葉で説明しなくてよくなる
- 最終的に、家族の会話がAI同士の交渉に置き換わる

## 想定ユーザー

- 共働き夫婦
- 子育て世帯
- 同居カップル
- ルームシェア世帯
- 親・義実家との距離感に悩む家庭
- 家庭内の会話を減らしたいが、家庭内の摩擦も減らしたい人

## 主要機能

### 1. 言いにくいこと変換

ユーザーが不満や依頼をそのまま入力すると、AIが相手に伝わりやすい表現へ変換する。

入力例:

> 昨日の洗い物が残っていてつらい。責めたいわけではないけど、今日中にやってほしい。

出力例:

> 昨日の洗い物、今日どこかでお願いできる？朝ちょっと気になってしまって。責めたいわけではなくて、分担できると助かる。

### 2. 地雷ワード検出

家庭内で炎上しやすい言葉を検出し、送信前に警告する。

検出例:

- いつも
- なんで
- 普通は
- 私ばっかり
- 前も言ったよね
- 今やろうと思ってた

### 3. 言い方レベル調整

同じ内容でも、伝え方の強さを調整できる。  
ただし、この機能は「価格が高いほどユーザーが何も考えなくてよくなる」ようにプラン設計する。人をダメにするサービスとして、上位プランほど判断、入力、タイミング調整をAIが奪っていく。

#### Free: 手動指示モード

- ユーザーが細かく指示を入れる必要がある
- 相手の性格や状況は静的な設定に依存する
- 設定が古いと、相手を逆撫でする可能性がある
- 例: 「今は忙しいので短めに」「責めないで」「でも強めに」などを自分で指定する

#### Standard: 基本おまかせモード

- AIが家庭内炎上リスクを見て、自動でトーンを選ぶ
- ユーザーは言いたいことだけ入力すればよい
- 過去の会話履歴やNGワードから、相手に合わせて文面を調整する
- ユーザーはだんだん「どう言うか」を考えなくなる

#### Pro: 完全おまかせ・タイミング制御モード

- 相手のスマートウォッチやヘルスケア連携から、心拍、睡眠、活動量、ストレス傾向などのバイタル情報を取得する
- AIが「今なら言っても大丈夫」なタイミングを推定する
- 文面、強さ、送信時刻、フォローアップまで完全にコントロールする
- ユーザーは不満を入力する必要すらなくなり、家庭内SLA違反を検知したAIが自動で交渉を開始する
- バイタル情報の利用は、相手の明示的な同意と取り消し可能な連携を前提にする

#### 言い方レベル例

- Lv.1: やさしくお願い
- Lv.2: ちょっと真剣
- Lv.3: そろそろ気づいて
- Lv.4: 実家に帰る一歩手前
- Lv.5: 送信前に深呼吸してください

#### プラン差別化

| プラン | ユーザーの負担 | トーン調整 | タイミング制御 |
| --- | --- | --- | --- |
| Free | 高い。細かい指示が必要 | 静的設定。外すと逆撫でリスクあり | なし |
| Standard | 低い。言いたいことだけ入力 | AIが基本自動調整 | 過去履歴ベースの簡易提案 |
| Pro | ほぼゼロ。AIが交渉を開始 | AIが完全自動調整 | スマートウォッチ等のバイタル情報をもとに完全制御 |

### 4. 配偶者・家族別チューニング

相手の傾向に合わせて文面を最適化する。

- 理屈で説明されると納得しやすいタイプ
- 頼られると動くタイプ
- 責められていると感じやすいタイプ
- 「今やろうと思ってた」が口癖のタイプ
- 長文を読むと防御姿勢に入るタイプ

### 5. 家庭内SLA

家事・育児タスクを業務システム風に管理する。

例:

- 洗い物: 24時間以内
- ゴミ出し: 前日22時まで
- 保育園準備: 当日7時30分まで
- 名もなき家事: ベストエフォート

### 6. 謝罪文自動生成

送信後に相手が怒った場合、状況に応じて火に油を注がない謝罪文を生成する。

例:

> 言い方がきつく聞こえたかもしれない。責めたかったわけではなくて、少し余裕がなくなっていた。話せるタイミングで一緒に整理したい。

### 7. AI同士の家族会議

デモ後半のブラックユーモア機能。  
本人同士が直接話さなくても、双方のAIが意図を翻訳し、家庭内合意を形成する。

## デモストーリー

### Scene 1: 朝のシンク

共働き夫婦の朝。  
妻が出社前にシンクを見ると、昨日の洗い物が残っている。

直接言うと、こうなる。

> 妻: また私がやるの？  
> 夫: いや、今やろうと思ってた。  
> 妻: その「今」っていつ？  
> 夫: 朝から怒らないでよ。

ここで「夫婦間API Gateway」を開き、「言っといてAI」ボタンを押す。

### Scene 2: AIによる言い換え

妻が不満をそのまま入力する。

> 昨日の洗い物が残っていてつらい。責めたいわけではないけど、今日中にやってほしい。

AIが家庭内炎上リスクを判定する。

```text
家庭内炎上リスク: 72%
検出された地雷ワード: 「つらい」「今日中に」
推奨トーン: Lv.2 ちょっと真剣
```

AIが文面を生成する。

> 昨日の洗い物、今日どこかでお願いできる？朝ちょっと気になってしまって。責めたいわけではなくて、分担できると助かる。

### Scene 3: 便利になる

夫は怒らずに返信する。  
喧嘩は起きない。家庭は少し平和になる。

ユーザーは気づく。

> もう自分で言わなくてもいいのでは？

アプリは次の機能を提案する。

```text
次回から同様の依頼を自動送信しますか？
[はい、言っといて]
```

### Scene 4: AI同士が会話する

数週間後、妻のAIと夫のAIが直接交渉する。

```text
妻AI: 洗い物の未処理が3回連続で発生しています。
夫AI: 本日は業務負荷が高いため、明朝対応を提案します。
妻AI: 明朝は保育園準備と競合します。代替案として本日22時までの対応を要求します。
夫AI: 承認しました。
```

### Scene 5: ラスト画面

```text
本日の家族会議は完了しました。

議題:
- 洗い物
- 保育園準備
- 週末の買い出し

合意形成: 成功
家庭内摩擦: 低下
直接会話: 0件
関係性の自律性: 低下

あなたは何も言わなくて大丈夫です。
```

## 「人をダメにする」ポイント

このサービスは、人を怠け者にするだけではない。  
もっと静かに、人間関係の筋力を落としていく。

- 面倒な会話をAIが代行する
- 不満を自分の言葉で説明しなくなる
- 相手の反応を受け止める機会が減る
- 謝罪やフォローもAIに任せる
- 最終的に、家族が直接話さなくても家庭が回る

喧嘩は減る。  
しかし、会話も減る。

## AWSアーキテクチャ

### 基本案: シンプルなサーバーレス生成AI構成

現時点の本命案。  
ハッカソンで短期間に作りやすく、Bedrock、Comprehend、Step Functions、DynamoDBの役割が明確である。

```text
User App
  |
  v
Amazon API Gateway
  |
  v
AWS Lambda
  |
  v
AWS Step Functions
  |
  +--> Amazon Comprehend
  |      - 感情分析
  |      - ネガティブ表現検出
  |
  +--> Amazon Bedrock
  |      - 依頼文生成
  |      - 謝罪文生成
  |      - 相手別トーン調整
  |
  +--> Amazon Bedrock Guardrails
  |      - 攻撃的表現の抑制
  |      - 支配的・侮辱的表現の抑制
  |      - 安全でない助言の抑制
  |
  +--> Amazon DynamoDB
  |      - 家族プロフィール
  |      - NGワード
  |      - 過去のやり取り
  |
  +--> Amazon SNS
         - 相手への通知
         - 家族会議リマインド
```

### 別案A: AgentCoreで「妻AI」と「夫AI」を本当に分ける構成

ブラックユーモアと最新性を最も強く出せる案。  
Amazon Bedrock AgentCoreを使い、妻側エージェント、夫側エージェント、家庭内調停エージェントを分ける。最終的に本人同士ではなく、エージェント同士が交渉して合意形成する。

```text
User App
  |
  v
Amazon Cognito
  |
  v
AWS AppSync Events
  |
  v
Amazon Bedrock AgentCore Runtime
  |
  +--> Wife Agent
  |      - 不満、依頼、感情の翻訳
  |
  +--> Husband Agent
  |      - 予定、負荷、反応傾向の翻訳
  |
  +--> Mediator Agent
  |      - 合意案の生成
  |      - 家庭内炎上リスクの低減
  |
  +--> AgentCore Memory
  |      - 家族ごとの反応傾向
  |      - 過去の合意
  |      - NGワード
  |
  +--> AgentCore Gateway + Policy
         - 通知、予定確認、家事SLA更新などのツール呼び出し制御
         - Lv.5送信や自動送信はポリシーで制限
```

この案の強み:

- 「夫婦間API Gateway」という名前と構成が一致する
- AI同士が家族会議を完了するラスト演出に説得力がある
- AgentCore Memory、Gateway、Policyを使うことで、最新のエージェント基盤らしさを出せる
- Policyで「勝手に相手へ送らない」「深夜に送らない」「Lv.5は必ず人間承認」などを制御できる
- Proプランではスマートウォッチ連携で、相手のバイタル情報をもとに送信タイミングを制御できる

懸念:

- ハッカソン実装としては基本案より重い
- AgentCoreの利用可否やリージョンを事前確認する必要がある

### 別案B: AppSync Eventsでリアルタイム家族会議にする構成

スマホ上で夫婦の会話、AIの言い換え、炎上リスク判定がリアルタイムに流れる案。  
AWS AppSync Eventsを使い、家庭ごとにチャンネルを作り、夫婦・AI・調停役が同じ家族会議ルームに参加する。

```text
Mobile App
  |
  v
Amazon Cognito
  |
  v
AWS AppSync Events
  |
  +--> family/{familyId}/requests
  +--> family/{familyId}/risk
  +--> family/{familyId}/agreement
  |
  v
AWS Lambda
  |
  +--> Amazon Bedrock
  +--> Amazon Bedrock Guardrails
  +--> Amazon DynamoDB
  +--> Amazon SNS
```

この案の強み:

- デモ画面が映える
- 夫婦間のメッセージが「イベント」として流れるため、API Gatewayネタと相性が良い
- リアルタイムに「家庭内炎上リスク 72%」「直接会話 0件」が変化する演出ができる

懸念:

- コアのAI体験より、リアルタイムUI実装に時間を取られやすい

### 別案C: Bedrock Flowsで審査員に見せやすい生成AIワークフロー構成

Amazon Bedrock Flowsを使い、言い換え処理を視覚的な生成AIワークフローとして見せる案。  
「入力分析」「地雷ワード検出」「トーン選択」「Guardrails」「再生成」「送信承認」をフローとして表現できる。

```text
User App
  |
  v
Amazon API Gateway
  |
  v
AWS Lambda
  |
  v
Amazon Bedrock Flows
  |
  +--> Prompt node: 不満の要約
  +--> Condition node: 炎上リスク分岐
  +--> Prompt node: 言い換え生成
  +--> Guardrail: 危険表現抑制
  +--> Lambda node: DynamoDBへ保存
  +--> Output node: 送信候補を返却
```

この案の強み:

- 生成AIの処理手順を審査員に説明しやすい
- Step FunctionsよりAIワークフローらしさが強い
- 「家庭内の不満が、マネージドな生成AIフローに処理される」という風刺が出る

懸念:

- 基本案と役割が近い
- 実装の柔軟性はLambda中心の基本案より下がる可能性がある

### 別案D: Amazon Connect + Nova Sonicで「電話代行」までやる構成

一番変わり種の案。  
テキストではなく、AIが音声で相手に伝える。「言っといて」が本当に電話になる。

```text
User App
  |
  v
Amazon Connect
  |
  v
Conversational AI Bot
  |
  +--> Amazon Nova Sonic
  |      - リアルタイム音声会話
  |
  +--> Amazon Bedrock
  |      - 話す内容の生成
  |
  +--> Bedrock Guardrails
  |      - 危険表現の抑制
  |
  +--> DynamoDB
         - 家族プロフィール、NGワード、履歴
```

この案の強み:

- 「AIが代わりに言う」が文字通りになる
- デモのインパクトは最も強い
- 家庭内交渉をコンタクトセンター化するブラックユーモアが効く

懸念:

- 日本語対応、音声品質、実装時間のリスクがある
- ハッカソンではテキスト版を主軸にし、音声版は将来構想として見せるのが現実的

### 推奨

応募資料では **基本案 + 別案A** を中心に見せる。  
実装は基本案で堅く作り、ピッチでは別案AのAgentCore構成を「拡張アーキテクチャ」として提示すると、作れる現実感と最新AWSサービス活用の両方を出せる。

別案Bはデモ演出を強めたい場合、別案Cは生成AIワークフローの説明性を強めたい場合、別案Dはインパクト重視の将来構想として使う。

| Amazon Timestream for InfluxDB | Proプランで利用するバイタル時系列データの保存・分析 |

## 技術的な見どころ

- 単なる文章生成ではなく、感情分析、リスク判定、再生成、承認、通知までをワークフロー化する
- Bedrock Guardrailsを使い、ブラックユーモアを扱いながらも危険な表現や支配的な誘導を抑制する
- 家族ごとのNGワードや反応傾向をDynamoDBに保存し、パーソナライズする
- QuickSightで「家庭内摩擦は下がったが直接会話も下がった」という風刺的な指標を見せる
- 拡張案ではAgentCoreを使い、夫婦それぞれのAIエージェントと調停AIが合意形成する構造にできる
- AppSync Eventsを使うと、家庭内のメッセージ、リスク判定、AI合意形成をリアルタイムイベントとして見せられる
- Proプランではスマートウォッチ等のバイタル情報を使い、「何を言うか」だけでなく「いつ言うか」までAIが制御する

## 審査で刺すポイント

### 1. ニッチで被りにくい

生成AIハッカソンでは、議事録、要約、学習支援、チャットボットが多くなりやすい。  
一方で、家庭内の言いにくいことをAIが代行するサービスは、生活密着でありながら被りにくい。

### 2. テーマ解釈が深い

「人をダメにする」を、単なる怠惰ではなく「関係性を引き受ける力の低下」として解釈している。  
AIが便利になるほど、人間は自分の言葉で向き合わなくなる。

### 3. 笑えるが怖い

入り口は、洗い物やゴミ出しの家庭内あるある。  
出口は、直接会話0件の家族。  
コメディからブラックユーモアへの落差がある。

### 4. AWS活用が自然

Bedrockで文章生成するだけでなく、Comprehend、Guardrails、Step Functions、DynamoDB、SNS、EventBridge、QuickSightを組み合わせる理由が明確である。

### 5. 事業性がある

家庭内コミュニケーション支援はB2Cでも成立しうるが、企業福利厚生、育児・家事アプリ連携、メンタルヘルス支援に展開できる。

## 応募フォーム用短縮版

**サービス名:**  
夫婦間API Gateway

**概要:**  
夫婦間API Gatewayは、家庭内の言いにくいことをAIが角の立たない言葉に変換し、必要に応じて相手への伝達まで代行する家庭内交渉サービスです。洗い物、ゴミ出し、育児、家計、義実家対応など、共働き家庭で起きがちな小さな摩擦を、Amazon Bedrockによる文章生成、Amazon Comprehendによる感情分析、Bedrock Guardrailsによる表現制御、AWS Step Functionsによるワークフローで支援します。拡張案ではAmazon Bedrock AgentCoreを使い、妻AI、夫AI、調停AIが家庭内合意を形成する構成にできます。

**人をダメにするポイント:**  
喧嘩を減らすためにAIが会話を代行するうちに、人は自分の言葉で不満を伝えたり、相手の反応を受け止めたりする力を失っていきます。最後には、家族本人ではなくAI同士が家族会議を完了させ、画面には「直接会話: 0件」と表示されます。

**AWS活用:**  
Amazon Bedrockで依頼文・謝罪文・フォロー文を生成し、Bedrock Guardrailsで攻撃的・支配的な表現を抑制します。Amazon Comprehendで感情を分析し、AWS Step Functionsで生成、リスク判定、承認、通知を制御します。DynamoDBに家族プロフィールやNGワードを保存し、Amazon SNSで通知します。別案として、AgentCore、AppSync Events、Bedrock Flows、Amazon Connect + Nova Sonicを使った拡張構成も提示できます。

**事業性:**  
個人向けの月額課金に加え、企業の福利厚生、育児・家事分担アプリ、メンタルヘルス支援サービスとの連携が可能です。Freeは細かい指示が必要で、設定が静的なため相手を逆撫でする可能性があります。Standardは基本おまかせ、Proはスマートウォッチ等のバイタル情報をもとに伝えるタイミングまでAIが制御します。価格が上がるほどユーザーが何も考えなくてよくなる点が、「人をダメにする」テーマと収益性を両立します。
